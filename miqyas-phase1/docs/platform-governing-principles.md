# المبادئ الحاكمة وخريطة مراحل الأدوات

> مرجع أساسي للتجربة والتوسعة. يُراجع قبل أي إضافة جديدة.

## المبدأ الحاكم (ثابت)

**أي إضافة تُدمَج في المنصة مع الأدوات السابقة — لا تُبنى كنظام موازٍ.**

- لا حذف لمسارات أو جداول قائمة؛ التوسعة تراكمية.
- لا نموذجي كتابة لنفس الكيان (مثال: المؤشرات تُكتب في `/admin/kpis` فقط؛ الكتالوج عرض).
- لا إسناد ثانٍ موازٍ؛ متطلب قياس واحد ومالك واحد يظهر في `/my`.
- المسارات الجديدة تُسجَّل في [`src/lib/phase-registry.ts`](../src/lib/phase-registry.ts) وتُوسَم في القائمة وفي شريط الأداة.

## أوسمة المراحل (للتجربة)

| الوسم | المعنى |
|-------|--------|
| **أصل** | أدوات القياس والاعتماد والإدارة الأساسية |
| **م1** | مكتب الاستراتيجية (كتالوج عرض + رزنامة + أوسمة تغذية) |
| **م2** | المراجعة الداخلية (لاحقاً — مدموجة تحت `/audit` دون فصل المنصة) |
| **م3** | لجنة المراجعة واللوحة المشتركة (لاحقاً) |
| **تجربة** | بيئة تقييم الأدوات |

## خريطة الأدوات الحالية

| المسار | الوسم | الاندماج |
|--------|-------|----------|
| `/my` | أصل | إدخال الشواهد |
| `/dept-follow` | أصل | اعتماد مبدئي |
| `/approvals` | أصل | اعتماد نهائي |
| `/dashboard` `/executive` | أصل | لوحات |
| `/strategic` … `/knowledge` | أصل | مسارات القياس (الحوكمة مربوطة بمتطلب م1) |
| `/admin/kpis` | أصل | كتابة المؤشرات الموحّدة (+ أوسمة م1) |
| `/admin/assign` | أصل | إسناد المالك |
| `/admin/*` أخرى | أصل | إدارة النظام |
| `/strategy` | م1 | عرض الكتالوج → يعدَّل من إدارة المؤشرات |
| `/calendar` | م1 | رزنامة القسم |
| `/uat` | تجربة | تقييم دون استبدال الأصل |

## قاعدة عند إضافة أداة جديدة

1. حدّد المرحلة (`م2` / `م3` / …).
2. ادمج مع جداول/واجهات قائمة إن وُجدت؛ وإلا أضف جدولاً جديداً **وربطه** بالمتطلب/المؤشر/المستخدم.
3. سجّل المسار في `phase-registry.ts` وأضف بند التنقّل بوسم المرحلة.
4. حدّث هذا الملف وخارطة الطريق بسطر واحد.
